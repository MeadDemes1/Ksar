# Ksar 3.1 - the third chip slot and idle moments

## What was added
- **Light chip, the third slot** (`standard`, `advanced`, `light`). A small model that is used only while you are not
  talking to Ksar. It is never used for your chat.
- **Idle worker.** After 20 s of quiet (`/config set idle.after <seconds>`) Ksar does one small job at a time:
  1. **warm** - loads the standard model into RAM (also right at start-up), so your first message does not wait
     for the model to load.
  2. **consolidate** - turns your latest chat exchanges into memory on the light chip.
  3. **split** - branches a memory note that has grown too big, on the light chip.
  4. **doctor** - once a day checks the memory notes for damage (no model; it only reports).
- **Safer background memory.** A small model must not be able to damage memory, so in the background it may only
  ADD facts, and only facts whose wording is really found in what you said (word-stem check). Corrections,
  replacements and invented facts are dropped. Anything it cannot verify waits for a normal save (`/save`, "remember",
  every 8 exchanges, `/exit`), which uses the standard model.
- **Faster chat prompt.** The chat history now shrinks in steps (to half) instead of one message per turn, so Ollama
  can reuse its cached prompt for several turns in a row (`recent_messages` default 16, plus `history_chars`).
- `/idle [status|on|off|now]`, `/chip` shows the light slot, `/chip load light`.

## How it works
- You press Enter: the idle worker stops at once. A running light-model call is cancelled at its next token by closing
  the connection, so Ollama stops generating. Your answer is not slowed down.
- You get your answer: the quiet period starts again.
- The model call of a background job runs WITHOUT any lock. Memory is read and written only while holding the app
  lock, which the console holds while it runs your command, so chat and background work can never write at the same
  time. If a normal save happened while the light model was thinking, its result is discarded.
- A failed job (Ollama down, model missing) waits 10 minutes before it is tried again and never interrupts you.
  Results show up as `(idle) ...` lines before your next prompt and are logged in `ksar_data/logs/idle.log`.
- The light chip needs about 1.5 GB, so it fits next to the 8B model (about 6.6 GB) in 32 GB. It unloads itself after
  5 minutes (retention `balanced`; `persistent` keeps it 30 min, `aggressive` unloads at once).

## How to use
```
ollama pull qwen3:1.7b
/config set chips.light qwen3:1.7b
/chip status            # the light slot should show as installed
/idle                   # what the worker did, what is waiting
/idle now               # run one job right now
/idle off               # switch background work off
```
`qwen3:4b` (about 2.6 GB) is a stronger choice for the light slot if the background saves seem too thin.
Without a light chip, only **warm** (and the daily check) run; memory is saved by the normal save points.

## Needs
- Python 3.10+, Ollama 0.9+, the light model pulled (`ollama pull qwen3:1.7b`).
- Optional Ollama server settings that often help on a laptop (set as environment variables before `ollama serve`,
  then restart Ollama): `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_NUM_PARALLEL=1` (smaller memory use per model),
  `OLLAMA_MAX_LOADED_MODELS=2` (standard + light together). Try them one at a time and compare the tok/s line.

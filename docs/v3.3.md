# Ksar 3.3 (0.3.3) - connected memory, autonomous memory management, time awareness

## What was added
1. **A connected, Obsidian-style memory** on top of the existing Markdown notes: CORE -> branches -> focused notes, with
   physical folders, meaningful links and relation types. Nothing was replaced; old notes work unchanged.
2. **Better extraction.** A new pipeline (prepare -> model -> plan -> apply) saves what matters (preferences, restrictions,
   corrections, goals, decisions, environment, incidents), rejects what is not supported by the owner's own words, never
   writes placeholders, and never creates empty notes.
3. **Proactive retrieval.** Ksar looks in memory by itself when a message clearly benefits from it, in three levels
   (core, branch, notes), with restrictions always surfacing when a relevant action is considered.
4. **An independent background worker.** Memory is saved by a persistent job queue; chat never waits for it and the worker
   no longer shares the global lock with the foreground.
5. **Time awareness**, deterministic and cheap: timezone-aware clock, session/idle tracking, noticing when you come back.
6. **Commands:** `/memory status|tree|search|backlinks|graph|check|queue|organize|save|time`, `/time`, `/save [wait]`.
Fixes found on the way: Ksar used to drop things the owner added to a note in Obsidian (extra front-matter keys such as
tags/aliases, free text under the title or under Facts); summaries containing `: ` produced invalid YAML properties.

## The memory hierarchy
```
core.md  (central navigation note, tiny, cached in RAM)
  |- User/                 branch "user"
  |     |- Preferences/    branch "preferences"  -> communication-style.md, programming-assistance.md ...
  |     |- Rules/          branch "rules"        -> file-permissions.md ...
  |     '- Goals/          branch "goals"        -> education.md ...
  |- Projects/             -> ksar.md ...
  |- Knowledge/  People/  Episodes/ (-> incident notes, day-YYYY-MM-DD)
  '- any new branch the amount of information justifies
```
- **Branches are created on demand**, only when a real note goes under them, so the vault never fills up with empty pages.
  The standard branches are user, preferences, rules, goals, projects, knowledge, people, episodes; the model may name a new
  one. A branch note's summary is kept current as `<description> | contains: child titles` (rewritten only when it changes;
  a branch whose summary you rewrote by hand is left alone).
- **Notes are small and focused.** The same note can be referenced from several branches with `[[wikilinks]]`; it is never copied.
- **Relations.** The `## Links` section already supported `- [[target]] (relation)`. Vocabulary: parent/child, explains,
  caused_by, related_to, contradicts, supersedes, belongs_to, originated_from. A restriction that came from an incident is linked
  `caused_by` the incident note.
- **Fact kinds** are Obsidian-style inline tags at the end of the fact: `#rule`, `#preference`, `#goal`, `#decision`,
  `#environment`, `#incident`, `#temporary`. Older versions simply see ordinary text; Obsidian shows real tags.
- **Facts keep** confidence (inferred / stated / verified), date and a source such as `chat:2026-11-19#4`, which is the journal turn
  the owner's words came from (`/memory open` and the journal files show it).

## CORE and its cache
- The core note keeps the id `core` and the file name `core.md` (changing a note's id would break links and sources; Obsidian
  shows it as "Core"). It holds a short profile, important stable preferences, restrictions and main projects, plus links to the
  branches. Pointers such as `Never delete files without asking first [[file-permissions]] #rule` are added when something is
  important enough. The core is capped (16 lines, 1,600 characters); beyond that the detail simply stays in its own note.
- It is loaded once and its digest is **cached in RAM**; it is rebuilt only after the core note really changes (a Ksar write, or an
  edit you made in Obsidian, noticed by the next background sync). A test counts the rebuilds: 25 retrievals rebuild it zero times.
- Plain chat does not get the core: the cached chat prompt is unchanged. The core digest travels with memory only when memory is
  injected because the message needs it.

## Automatic retrieval (no extra model call)
Three levels, all answered from RAM:
1. **Core** - the cached digest.
2. **Branch** - which branches does the request point at? (BM25 over branch titles and summaries, which list their children.)
3. **Notes** - BM25 over the detailed notes, boosted inside the matching branch, then a bounded one-step walk along
   meaningful links (explains, caused_by, originated_from ...; at most 3 extra notes), then fact-level selection (confidence
   weighted: verified > stated > inferred; newer facts first when the request is about time).
- **Restrictions** (`#rule` facts) are checked separately: if the request touches what a rule covers, the rule is injected first,
  together with the incident that explains it, whatever the rest of the ranking says.
- **Gate.** Memory is injected without being asked only when the match is strong (2 or more rare terms, or one rare term that
  is in a note's title/summary, or a rule applies). "What is the capital of France?", "explain recursion" and "hi" inject nothing.
  Explicit requests ("what do you know about me") always look. With tools offered, applicable rules are added to the request.
- The memory text is appended to the one message that needs it, never to the system prompt, so Ollama's prompt cache stays valid.
- **Inspect it:** `/why` lists what was used and why; `/memory search <query>` shows scores, matched terms, branches and rules.
- The search index lives in RAM and is updated incrementally from the store's change log; deleting everything cached just
  rebuilds it from the Markdown (14 ms for 400 notes). Measured: a retrieval takes 0.14 ms at 30 notes, 0.7 ms at 400, 3.8 ms at 2,000.

## Extraction
`prepare` builds a prompt from the journal turns plus related notes (RAM only). The model proposes JSON operations. `plan` then
validates everything and never writes; `apply` writes the accepted plan in short store operations and never calls a model.
- Each proposed fact must carry **evidence**: the owner's exact words. Evidence must exist in the owner's messages.
- **Grounding** compares meaning, not just words: groups such as like/love/prefer or delete/erase/remove count as one concept;
  numbers and names must match exactly; negation must agree (`May delete files` is not supported by `never delete my files`).
  Long sources are judged sentence by sentence.
- A **borderline** fact (partly supported) gets one short yes/no question to the background model about that exact quote. `yes`
  saves it as `inferred` (a model's judgement never becomes `stated`), `no` drops it, `unsure` keeps it **pending**: it is
  re-checked later against the next 7 days of conversation and dropped after 14 days.
- Placeholders (`unknown`, `n/a`, `not specified`, `?`, Russian equivalents) are never saved. A note is only created if at least one
  of its facts survives. A proposed note that is clearly the same subject as an existing one is merged into it.
- **Confidence rules.** The model can never assign `verified`. Facts learned after untrusted content are `inferred`. A less
  reliable claim never replaces a more reliable one with the same key (it goes to the `review` note). A newer `stated` fact
  replaces an older `stated` one and the old one stays in history.
- **Restrictions are never downgraded.** A new fact cannot replace a rule; a contradicting rule is added next to the old one and a
  review entry is written ("Conflicting rules ... ask the owner").
- Corrections are only accepted from the Basic chip, never from the Idle/Light chip, and must themselves be grounded.
- A long conversation is processed as one coherent episode (up to 8 exchanges together, in chunks of about 9,000 characters).

## The background worker
- `Conversation.send` writes the journal, puts an `extract` job on the **persistent queue** (`memory/.jobs/queue.json`) and returns.
  Pure memory commands ("remember the important things we discussed during the last hour", "save this conversation", Russian too)
  are answered instantly ("Okay, I'll process that in the background.") without any model call; a message that carries content
  ("remember that my dog is Rex") is answered normally and extracted from the journal like everything else.
- Jobs have an id, type, creation time, status, priority, source references, attempts, retry time and result. Identical jobs are
  not queued twice. Failures back off (5 min x attempts) up to 3 tries. Running jobs found after a crash go back to pending.
  If the queue file is lost, journal turns that never reached memory are queued again at the next start (older conversations are
  treated as already handled on the first start of this version).
- Job types: `extract`, `recheck` (pending facts), index upkeep, `split`, daily `check` (doctor + graph validation), `organize`
  (off by default), time upkeep. Order: warm model, extract, recheck, index/sync, split, check, organize, clock.
- **Chip:** the Idle/Light chip when configured, otherwise Basic, chosen with `/config set memory.chip auto|light|standard`.
  The Idle chip still never answers chat.
- **Concurrency.** The worker never takes `app.lock`; nothing slow runs under any lock. The store has one small lock around single
  operations (a file write plus snapshot, milliseconds). The model call and all validation happen without locks. Every plan
  records the revision (mtime+size) of the notes it was built from; `apply` refuses (`Conflict`) if any changed, and the job is
  planned again from fresh data (up to 3 times). Fact appends always go to the latest version of a note, so newer foreground
  data and your manual edits are never overwritten. When you press Enter, a running background call is cancelled at its next
  token and the job returns to the queue unharmed.
- **Quiet.** Nothing from the worker is printed into the conversation (`/config set idle.notify true` re-enables the old
  "(idle) ..." lines). Inspect with `/idle status`, `/memory status`, `/memory queue`, and `ksar_data/logs/idle.log`.
- Without a running worker (library use, `/idle off`) memory is saved synchronously with the same pipeline, as before.

## Organization and maintenance
- New notes go into branch folders (`User/Rules/`, `Projects/` ...). The file name stays the note id, so `[[wikilinks]]`, parents,
  sources and history are unaffected by where a note lies.
- **Existing notes are not moved.** `/memory organize` lists what would move; `/memory organize apply` does it;
  `/config set memory.organize true` lets the worker do it gradually (3 notes per run, only notes untouched for 10 minutes).
- `/memory check [fix]` = memory doctor plus graph checks (broken `[[links]]` in facts, duplicate titles). The worker runs the same
  check once a day and only reports.
- External edits (Obsidian, an editor) are noticed by a cheap sync every 30 s while idle (and by `/memory sync`); a note you
  edited is treated as authoritative: Ksar only ever appends to its current content.

## Obsidian
Open `ksar_data/memory/` as a vault. I read the official pages on [Internal links](https://help.obsidian.md/links) and
[Properties](https://help.obsidian.md/properties), and [Graph view](https://help.obsidian.md/Plugins/Graph+view), and checked the vault against them:
- Notes use `[[note-id]]` wikilinks; ids are lowercase slugs, so they never contain the characters Obsidian forbids in a link
  target (`# | ^ : %% [[ ]]`). A test verifies that every link resolves to an existing file and that file names are unique.
- Front matter is YAML. Values containing `: ` or ` #` are now double-quoted (a bare one is invalid YAML and breaks the Properties
  pane); Ksar reads the quoted form back. Properties Ksar does not use (`tags`, `aliases`, `cssclasses`, in Obsidian's multi-line
  list format too) are preserved verbatim, property names stay unique.
- The graph draws links; a note grows with the number of notes that reference it, so rules linked from core, their branch and
  their incident become prominent. Every note is reachable from its branch (no orphans) and there are no links to missing notes.
  Local graph depth and filters are Obsidian's; no custom graph UI was added. `/memory graph <note>` gives a text view.
- `.history`, `.trash` and `.jobs` are dot-folders (hidden by Obsidian). `journal/` holds the raw conversation record.

## Time awareness (`ksar/timeinfo.py`)
- `TimeService`: timezone-aware now, timezone label, session start/age, last message and last answer (persisted in
  `config/session_state.json`, so a restart the next morning still knows), time since the previous message, date rollover.
- **Timezone:** the operating system's (including daylight saving) unless `/config set time.zone Europe/Berlin`; on Windows an
  IANA name needs `pip install tzdata`, otherwise Ksar says so and uses the OS zone. Nothing is hard-coded.
- **When the model hears about time:** only (a) when the message is about time/dates ("what day is it", "tomorrow", "how long
  ago" ...), or (b) once after a pause longer than `time.gap` hours (default 4): "The owner is back after 9 hours (their previous
  message was yesterday at 22:40). It is now Thursday 08:15, a new day. You may acknowledge this naturally once if it fits; do not
  guess what they did in the meantime." It is added to that one message only: the cached system prompt never changes, there is
  no greeting after a short pause, none repeated in the same session, and nothing is claimed about sleep or activity.
- The worker notices the date change (deterministic, no model) and re-arms the daily check. `/time` shows the clock and session.
- Notes keep their existing local-time ISO timestamps (for compatibility); the queue, the time service and logs use aware ones.

## How to use
```
/memory status                  notes, branches, folders, core cache, index, queue, last consolidation
/memory tree                    hierarchy with folders
/memory search <query>          what would be retrieved, with scores and reasons (also /why after a message)
/memory backlinks <note>        who links here        /memory graph <note>   local connections as text
/memory check [fix]             doctor + graph validation      /memory queue   background jobs
/memory organize [apply]        move old root-level notes into branch folders (nothing moves automatically)
/save            queue everything not yet processed          /save wait   process it now
/idle status                    worker, queue, last consolidation          /time   clock and session
/config set memory.async|memory.auto|memory.chip|memory.organize|idle.notify|time.zone|time.gap <value>
```
Old commands (`/tree /recall /open /history /restore /forget-note /purge /doctor /reflect`) work as before; `/reflect` and `/save` now queue.

## Migration and compatibility
- No migration step and no destructive change: existing notes load as they are, ids/links/sources untouched, nothing is moved,
  rewritten or regenerated at upgrade. New metadata is optional (inline tags, folders, relation names in the existing Links section).
- Files written by 0.3.3 follow the same front-matter keys and fact-comment syntax, so 0.3.2 can read them (it shows `#rule`
  as plain text, and quoted titles with their quotes).
- `queue.json`, the in-RAM index and the core cache are all rebuildable; deleting them loses nothing (a pending, not yet
  extracted conversation is re-queued from the journal).
- The first start of 0.3.3 treats existing journal turns as already handled (they went through the old process).

## Limitations
- Not run against a real Ollama in the build environment (a scripted model and fake HTTP server only). How well the model proposes
  notes and evidence quotes, and how often the grounding is too strict for a small model, must be seen on your machine; every raw model
  reply is recorded in `ksar_data/memory/.history/ops.log`, background results in `ksar_data/logs/idle.log`, and pending facts show
  up in `/memory queue`.
- The concept groups for paraphrase matching are small (about 20 groups, English and some Russian); everything else relies on word
  overlap plus the yes/no check. A paraphrase it cannot match waits as "pending" instead of being saved.
- Retrieval is lexical (BM25 + graph); there are no embeddings. A request that shares no words with a note will not find it.
- The relation labels are not enforced on notes written by hand. The core cap means the least important pointers may stay out of the core.
- Extraction waits for quiet time (default 20 s) and for Ollama; right after you leave, it may take a while for notes to appear
  (`/save wait` forces it). Queue entries and the journal survive a restart.
- Notes written before 0.3.3 stay in the vault root until you run `/memory organize apply` or enable the option.

## Postponed
Embeddings or semantic search, merging duplicate notes automatically (they are reported), splitting by topic with relation
suggestions, a dedicated daily-notes feature, mid-task chip escalation, sandboxed code execution.

## Needs
Python 3.10+, Ollama 0.9+, no new packages. Optional `tzdata` on Windows for named timezones.
